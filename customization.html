CONFIG.TOML

先建立保守、可理解的執行預設。

CLI 與 IDE 可使用 ~/.codex/config.toml 設定個人預設。可信任專案可用 .codex/config.toml 覆寫專案需求；這份設定檔不等同 ChatGPT 對話的自訂指示。

設定用途如何選
model_reasoning_effort支援模型的推理強度一般任務先用 medium，困難分析再提高
approval_policy何時提出批准請求on-request 搭配工作區限制，減少不必要的全面放行
sandbox_mode檔案／網路存取邊界workspace-write；批准與 sandbox 是兩個不同層次
web_searchcached／indexed／live／disabled版本或即時資料問題按需使用 live
[agents]子代理能力與並行數先以兩個獨立任務開始，詳細見多代理指南
套用前：先查看現有設定，避免重複 TOML table。以 codex --version 確認版本，重新啟動 session 後核對生效值；不支援的欄位請對照該版本文件。
PRECEDENCE

為什麼設定改了，行為卻沒變？

一般優先序由高到低：CLI 覆寫 → 可信任專案設定 → 選用的 profile → 使用者設定 → 雲端／系統預設 → 內建預設。管理者的強制要求另有約束力；不可信任的專案會跳過專案設定。

  1. 確認工作目錄、實際載入的設定與啟動參數。
  2. 找出重複的 model、搜尋與 agent 設定，檢查 TOML 區塊位置。
  3. 檢查專案信任狀態和組織限制。
  4. 只改一個選項，用小任務確認差異再繼續。
AGENTS.MD

把工作默契寫成可以驗證的規則。

跨專案偏好放 ~/.codex/AGENTS.md；專案共同規則放 repo 根目錄；局部慣例放工作目錄沿途的子目錄。每層優先找 AGENTS.override.md，再找 AGENTS.md，從外到內合併。它不會自動把每個子目錄的規則全文讀進來。

開新 session 後請 Codex 列出載入的規則來源，再用一個小任務確認。與其不斷增加規則，先刪除重複、衝突與過時的指示。

SKILLS + MCP

流程可重用，資料可按需取得。

Skill：教它如何完成一類工作

建立含 name、description 的 SKILL.md；描述適用情境，內文放步驟與交付條件。在 Codex CLI／IDE 用 /skills 或 $ 明確選用；也可依描述自動匹配。

MCP：讓它取得所需工具

以官方文件 MCP 為例，提供文件搜尋與讀取。連線本身不會執行 OpenAI API，也不代表每次自動查文件，應在任務或規則中明確要求。

先從唯讀文件工具開始。當流程已穩定且重複發生，再封裝 Skill；設定、規則與參考文件各自負責一件事，會更容易維護。

MEMORIES

讓有用的背景延續到下一次工作。

本機 Codex Memories 與 ChatGPT 網頁的記憶是不同機制。本機功能預設關閉，可在 Settings → Personalization 開啟，或在 config.toml 設定 [features] 下的 memories = true。

在互動 CLI 或桌面 App 用 /memories 控制目前對話是否使用或貢獻記憶。IDE 使用連接的 Codex host 記憶。記憶生成在背景進行，不保證任務結束後立即更新；必須每次遵守的規則仍放 AGENTS.md。

建議：先確認你希望保留哪些個人工作脈絡，再啟用。分享 Codex home 或記憶檔案前檢查內容；不要把 secrets 寫進記憶。
