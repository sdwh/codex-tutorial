LOCAL OR CLOUD?

先依資料和環境選表面

本機 Codex

適合依賴本機服務、私人檔案、快速來回 UI 調整，或需要你的開發環境時。

Codex Cloud

適合 repo 已連線、任務可獨立描述、需要在背景執行或與本機工作隔離時。可在可用介面從桌面版或網頁派送與追蹤。

切到 Cloud 不會自動解決模糊需求。還是要交代目的、環境依賴、允許使用的網路/憑證、測試方式和交付條件。可用性依帳戶方案和 workspace 設定。
ENVIRONMENT MANIFEST

派送前，寫清執行環境

Repo / Revision

哪個 repo、分支或基線？如何辨認要套用的變更？

Dependencies

需要哪些 runtime、套件、服務和 setup steps？

Network

任務是否需要外網？只允許取得哪些必要來源？

Secrets

是否真的需要憑證？用受控機制提供，避免把密鑰寫進 prompt、檔案或日誌。

Verification

測試、build、lint 命令與成功條件。

Deliverable

要回傳分支、patch、報告或其他可審核成果。

SCENARIO / BACKGROUND TASK

案例：Cloud 先檢查所有解析器的時區風險

你本機正在處理前端 UI；另一個任務可以獨立盤點 repo 中日期轉換和 UTC 使用方式，交付風險表與可重現測試建議。

這適合作為獨立調查，但不要讓 Cloud agent 同時修改同一批日期檔案。

任務描述要涵蓋

  1. 目標是調查與報告，不要直接重寫所有解析器。
  2. 搜尋日期 parse、format、資料庫欄位和使用者時區入口。
  3. 區分已確認問題、風險假設和無法判定處。
  4. 每筆發現附檔案/行號、影響範圍和重現案例。
  5. 不得讀取或輸出 secrets / 真實個資；測試使用合成資料。
HANDOFF BUILDER

建立可委派任務規格

LAB / 35 MIN

派送、追蹤、取回、整合

  1. 選一個可在獨立分支 / worktree 或 Cloud 環境工作的調查任務。
  2. 盤點環境依賴；不需要的網路和憑證不要開。
  3. 派送任務後，追蹤進度並在發現目標偏差時 steer。
  4. 任務完成時，先檢查報告和檔案差異，不要直接當成已合併。
  5. 在本機乾淨工作區套用 / cherry-pick / merge 之前確認基線。
  6. 本機重跑必要驗證，檢查整合後 diff，再決定是否接受。
判斷題：Cloud 任務回報所有測試通過，是否代表你可以直接合併？
