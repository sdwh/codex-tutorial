METHOD / THREE PASSES

三輪導覽：由廣到窄

Pass 1 · 地圖

讀 README、目錄結構、套件設定、啟動與測試命令。只建立地圖，暫不深入細節。

Pass 2 · 路徑

選一個使用者可見流程，追入口 → 核心邏輯 → 資料來源 / 輸出 → 測試。

Pass 3 · 假設

問清楚不確定處，列出證據和檔案位置，再開始變更。

Context budget（上下文預算）：一次只問一段流程，請 Codex 引用路徑和行號；摘要中保留可用於下一任務的事實，不要把所有探索逐字搬進新 prompt。

SCENARIO / CASE STUDY

案例：每週報表漏掉部分訂單

你剛加入一個服務，客服說「每週報表少算週日晚上建立的訂單」。你還不知道是排程、時區、查詢還是匯出造成。

先做唯讀探索，不先修。
  1. 確認專案如何啟動、測試與產生報表。
  2. 定位報表入口、資料查詢、日期區間計算和匯出模組。
  3. 追出時間的來源與時區轉換點；列出相關測試。
  4. 要求 Codex 把「已確認」和「推測」分開，並提供檔案/行號。
  5. 用一個具體時間例子重現，例如台北週日晚間對應的 UTC 日期。

GUIDED PRACTICE / 35 MIN

實作：接手一個陌生 repo

  1. 選一個你不熟悉但能執行的 repo，從 README 與目錄開始。
  2. 用全域地圖 prompt，檢查啟動和測試命令是否真能用。
  3. 選一條功能路徑追查；例如登入、搜尋、匯入或報表。
  4. 要求 Codex 找相關測試，指出目前覆蓋哪些案例、缺哪些邊界。
  5. 把你要接手的下一個任務寫成 3 句摘要，附檔案清單與未確認事項。

圖片與錯誤脈絡如何提供

若任務與介面、架構圖或錯誤畫面有關，附圖能減少口頭描述的落差。圖片旁仍要說明觀察重點、視窗尺寸、重現方式和預期行為。涉及敏感資料先遮蔽再附上。

不要只說「看截圖修好」。說出哪裡不符、怎麼觸發、在什麼環境出現，以及哪些元素不能改。
