QUOTA / WHAT TO KNOW

如何理解 Codex 使用量

在哪裡查

桌面版 Settings → Usage / Usage & billing；CLI 可用 /status 顯示目前工作階段和可用 rate limit（速率 / 用量限制）資訊。

為什麼不列固定訊息數

使用量受方案、模型、輸入輸出大小、任務長度、推理設定、執行方式及工具影響。同一方案的不同任務也可能差很多。

Allowance / Credits

Allowance（方案內含用量）、usage credits（可用於支援功能的額外點數）和 API 計費不是同一件事。可用選項按帳戶方案及 workspace 設定。

觀察哪種任務耗量高

大型 repo 探索、長對話、多輪工具操作和長時間 agent run 常比清楚的小任務耗用更多；縮窄範圍能讓工作更聚焦。

以帳戶內即時用量頁為準。不要根據網路上別人的固定數字推算自己的額度；若使用 API key，查 API Platform 帳務而不是 ChatGPT 用量頁。
PERMISSION MODEL

操作批准與 Sandbox 是兩條控制線

Read-only

適合先理解未知 repo；不能直接編輯工作區檔案。

Workspace-write

允許在指定工作區內修改和跑常見命令；越界時依設定詢問。

Full access

撤除重要限制；只在明確信任且必要時使用，注意檔案及網路影響。

批准某個操作並不代表整個任務獲得無限制權限；Auto-review（自動審查）也不會取消 workspace 的限制或取代所有批准。

CAPSTONE / PICK A BRIEF

畢業專案情境

日期區間漏資料

某報表遇到週日深夜資料少一筆。先追時間欄位、時區和 inclusive/exclusive 區間，再加邊界回歸測試。

搜尋頁加無結果狀態

搜尋沒有結果時頁面空白。保留現有版面，加入說明、清除搜尋動作和鍵盤可及性。

每月 CSV 匯出

建立符合目前篩選條件的 CSV 報表，避免輸出敏感欄位並處理特殊字元。

CAPSTONE RUBRIC

完成一個完整 Codex 任務循環

  1. 查 /status 或 Usage；確認目前用量提示、工作區和權限模式。
  2. 選一個情境，寫出目標、背景、範圍、限制、驗收條件。
  3. 要求 Codex 先探索；多步驟任務使用 Plan，審查依賴和風險。
  4. 分階段實作；中途偏離時 steer，補充規則或資料。
  5. 執行相關測試 / 手動流程；記錄實際命令和結果。
  6. 用 review 找具體問題；你本人逐一檢查 finding 和 diff。
  7. 整理交付摘要、剩餘風險和沒有跑的檢查。

畢業評分（每項 0–2 分）

需求清楚 · 範圍受控 · 有證據的驗收 · diff 可理解 · 安全邊界明確。8 分以上且沒有 0 分項，代表你具備日常獨立運用基礎。
