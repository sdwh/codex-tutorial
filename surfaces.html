NAME / MODE / ENVIRONMENT

入口、模式、執行環境分開看

入口：你開了什麼？

瀏覽器中的 ChatGPT，桌面 App 的 Codex 開發介面，或終端機裡的 Codex CLI。本站沿用「Codex App」稱呼桌面 Codex 介面；目前官方文件也稱 ChatGPT desktop app，從產品選擇器選 Codex。

模式：你怎麼交辦？

Chat 以問答、討論和逐輪調整為主；Work 以多步工作與可檢查的交付物為主。Codex 的 Plan 與 CLI 的非互動 exec 是另外的控制方式，不能視為同一組網頁模式。

環境：工作在哪裡跑？

網頁 Work 使用受管雲端環境；Codex App 可以使用本機、worktree 或已配置的 Cloud。CLI 通常在啟動它的主機／runner 工作；接到遠端 host 時再確認實際位置。

Work 是模式，不代表購買了名為 Work 的方案。Cloud 是執行環境，不代表所有網頁工作都是 Codex Cloud。功能依帳號、平台、推出進度與 workspace 設定提供。

四種入口各自帶來什麼？

入口開始方式與材料常見成果與操作本課程怎麼使用
ChatGPT Chat・網頁在 chatgpt.com 選 Chat；以訊息、上傳材料及已連接來源提供脈絡解釋、構想、討論與逐輪修改；工具依介面可用功能練習交辦、釐清需求與解讀錯誤；需實際操作 repo 時另確認執行工具
ChatGPT Work・網頁選 Work；上傳材料、連接工具；任務在受管雲端執行交付檔案、研究、網站或多步成果；可執行程式與 shell，依提供的環境生活、研究、資料與創作方法可轉用；本機路徑與工具要重新準備
Codex App・桌面選 Codex、連接專案，再選本機／worktree／Cloud看檔案差異、review、專案與工作執行緒；使用 App 控制與可用工具主要圖形介面路線：交辦、除錯、開發、Git 與驗收
Codex CLI・終端機在 repo 的 shell 啟動 codex；登入並確認工具與權限互動文字介面、slash 控制、codex exec、JSONL、腳本／CI 整合主要深度自動化路線：Hooks、批次、設定診斷與可重跑流程

ChatGPT Work 與 Codex 都能處理程式或非程式工作。選入口時先問：資料在哪裡？需要哪些工具？最後要下載檔案、看網站，還是 review Git 差異？

檔案與專案

CLI 從目前目錄或指定路徑工作；App 連接專案。本機 Codex 能讀到的檔案，不會自動提供給網頁 Work 或 Codex Cloud。ChatGPT Projects 的上傳檔與指示，也不等於連接整個本機 repo。

官方 Projects 說明 ↗

設定與記憶

本機 App 的 Codex agent、CLI 與 IDE 使用同一設定體系，App 有常用控制，進階設定可編輯 config.toml。網頁 Work 的受管環境不讀取你電腦的 Codex config；ChatGPT 網頁記憶與本機 Codex Memories 分開看。

客製化指南 →

Skills 與插件

本機 Skill 需位於 host 可探索的位置。Codex CLI／IDE 可用 $skill-name 或 /skills；ChatGPT 用支援的 @ Skill 選取／plugin。plugin 封裝能支援更多入口，但仍要核對工具、登入與 host。

ENTRY ≠ NEW QUOTA

Plus 的額度看登入與工具，不能只看入口

以 ChatGPT 帳號登入的 Codex 使用方案額度；ChatGPT Work 與 Codex 共用使用限制。切換 App／CLI／Cloud 不代表取得一份新免費額度。一般 Chat 的模型訊息限制依帳號畫面確認；API key 請查 API 帳戶計費。

任務大小、模型、並行與生圖都可能影響消耗。功能是否開放與當下餘額，請看自己的介面，不把範例當作每個 Plus 帳號均可使用的保證。
