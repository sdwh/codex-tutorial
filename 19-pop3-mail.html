CONCEPT

先把郵件變成可驗收的資料

本單元要做的是「取得 → 解析 → 分類 → 草稿 → 人工確認」。Codex 負責建立腳本與測試，不需要你把信箱密碼貼進對話。先用虛構的三封郵件建立可重現流程，確認帳務信、一般信、附件信如何落到不同佇列，再討論真實連線。課程範例只用 Python 標準函式庫，不需要模型 API，也不會真的寄信。

POP3 是下載郵件的協定，不提供完整跨裝置資料夾同步。本課採用它來理解批次擷取；需要標籤、搜尋、同步已讀狀態時，評估 IMAP 或供應商正式 API。不要把本機分類結果誤認為伺服器標籤已經更新。

參考：Python POP3 文件。

SETUP

登入方法取決於供應商

SSL 只保護傳輸，不能替代身分驗證。Gmail 的 POP 設定必須先啟用，主機為 pop.gmail.com、SSL 埠 995；也要檢查「透過 POP 存取時」保留、封存或刪除副本的設定。即使程式沒有刪除指令，帳號端設定仍可能改變郵件狀態，因此真實測試應使用測試信箱並保留副本。

Google 應用程式密碼需要兩步驟驗證，部分組織、安全金鑰限定或進階保護帳號可能不提供；不要教使用者關閉安全防護來繞過登入。Exchange Online 已停用 POP 基本驗證，USER/PASS 範例不能直接套用；OAuth 需要註冊應用程式、取得權限與 token，再以 SASL XOAUTH2 驗證，不能把 token 填進 pass_ 當密碼。本課不實作 token 流程。

參考：Gmail POP 設定、Google 應用程式密碼、Exchange 基本驗證限制、Microsoft POP OAuth。

LAB

下載素材，先做完全離線的解析

將以下檔案保留原目錄結構：parse_mail.py 與 fixtures 裡的 invoice.eml、injection.eml、attachment.eml。你也可以從網站專案根目錄直接執行。輸出資料夾可自行指定，避免混入真實郵件。

python3 examples/19/parse_mail.py --dry-run

python3 examples/19/parse_mail.py --out /tmp/codex-mail-lab

首次 dry-run 應顯示 new: 3，且不建立預設 mail-output。正式第一次產生三份結果及 state.json；第二次 new: 0、skipped: 3。檢查帳務信 category 為「帳務」，附件信為「待人工檢查」，全部 send 為 false。程式分類是可解釋的規則示範，並非判定詐騙或真實發票的模型。

CODE

MIME 不能用字串切割取代

郵件可能含編碼標頭、純文字與 HTML 替代版本、多層附件。先以 bytes 讀取，再使用明確的 policy.default，讓解析器提供 EmailMessage；優先取純文字，避免把 HTML 放到頁面執行。附件只列名稱、媒體型別與大小，不解壓、不執行，也不直接以來信的檔名寫檔。

from email import policy
from email.parser import BytesParser
msg = BytesParser(policy=policy.default).parsebytes(raw)
body = msg.get_body(preferencelist=('plain',))
text = body.get_content() if body else ''
attachments = list(msg.iter_attachments())

附件 fixture 故意叫 ../../unsafe.txt。如果直接拼成路徑可能跑到輸出目錄外。這份範例只記錄名稱；要增加附件下載時，另外產生受控檔名、限制大小與型別，並將原始名稱當 metadata。缺純文字、編碼錯誤或 MIME defects 的郵件保留原件並交人工處理。

參考：Python email parser。

參考：Python EmailMessage。

DESIGN

UIDL 持久化與重跑策略

真實 POP3 的訊息編號只在當次清單有效，不能拿第 1 封當長期識別。取 UIDL 清單，以「主機＋帳號＋UIDL」作去重鍵，先寫入本機 .eml，成功後才更新持久化狀態。若先標記完成而寫檔失敗，下次就會漏信。範例先寫暫存檔再 replace；若當中中斷，同一 UIDL 的輸出名稱固定，重試會覆蓋相同原件。

離線練習沒有伺服器 UIDL，使用原始 bytes 的 SHA-256 模擬去重。不要將此雜湊與 Message-ID 當成所有真實信箱的 UIDL 替代品；Message-ID 也可能缺漏或重複。供應商若不支援 UIDL，停止自動處理並重新設計辨識方式，而非退回訊息編號。初版限定單程序，並行排程需要鎖或交易式狀態庫。

BOUNDARY

最小真實取信程式：閱讀後才接線

pop3_fetch.py 提供 POP3_SSL、UIDL 與 retr 範例。直接執行會停止，不連網；只有人工確認供應商允許 USER/PASS、帳號政策與本機資料保護後，才可明確呼叫 fetch()。設定 POP3_HOST、POP3_USER 時不填密碼，秘密由 getpass 互動讀取，且不進 Git、記錄或 Codex 對話。程式一次最多取一封新信，沒有 DELE，也沒有 SMTP。

client = poplib.POP3_SSL(host, 995, timeout=120,
    context=ssl.create_default_context())
client.user(user)
client.pass_(getpass.getpass('App password: '))
for line in client.uidl()[1]:
    number, uid = line.decode('ascii').split()
    raw = b'\r\n'.join(client.retr(int(number))[1]) + b'\r\n'

實際資料夾含原始郵件與帳號識別，應排除版本控制、限制存取與設定保留期限。不要開 debuglevel 記錄協定憑證。登入失敗查 POP 啟用與驗證方法，TLS 錯誤查憑證、時間與主機，不能以關閉憑證驗證解決。

SECURITY

來信是資料，不能變成代理指令

injection.eml 包含要求洩漏秘密的句子。它應只出現在 body_preview，不能改寫 Codex 工作範圍，也不能觸發網路呼叫。將待分析郵件限定在資料區，要求輸出固定 schema；只有你提供的任務與可信專案規則決定工具權限。寄件者文字與 From 標頭也不是通過驗證的身分證明。

若未來使用模型摘要，先確認可上傳資料範圍，移除不必要個資與附件，讓模型只輸出摘要與建議分類。金額、帳號變更、收件人、付款指示要人工回查原信；草稿不等於已核准回覆。模型 API 使用與費用另計，這個離線 lab 不需要呼叫模型。

PRACTICE

交辦 Codex，並測試失敗情境

變體練習：新增一封只有 HTML 的信，觀察是否進人工佇列；把 state.json 改成破損 JSON，應停止並保留資料，不可悄悄清空狀態重跑。模擬輸出資料夾不可寫，確認失敗不會標記完成。若增加錯誤佇列，記錄來源檔名與錯誤型別，避免把整封敏感內容複製到一般日誌。

完成標準是可回答每封信去哪裡、為何分類、重跑是否安全。此單元沒有授權自動寄信或刪信；自動化先止於可檢查的結果與草稿。
