讓獨立工作同時推進

學會明確觸發 subagents、分配工作邊界、控制並行成本，最後由主代理整合與驗收。

最後查證 · 2026-10-10附可複製範本設定以目前版本為準
PARALLEL WITH PURPOSE

先判斷哪些工作可以獨立完成。

主代理負責需求與整合，子代理各自處理有明確輸出的小任務。最適合先並行的工作是讀碼、測試查核、文件研究與審查。

適合並行

一個代理查搜尋資料流，一個查鍵盤操作測試；兩邊唯讀，各自回報證據。

先排順序

修改 API 後才能更新依赖它的 UI；兩個代理同時改共用元件，也容易產生衝突。

Subagents 有獨立脈絡，但不保證檔案系統隔離。Git worktree 提供不同工作目錄；多代理協作與 worktree 是兩個不同機制。

TRIGGER

直接說：請使用子代理。

目前 Codex 文件說明：在 App、CLI 或 IDE 中明確要求委派獨立工作，或由適用的 AGENTS.md／Skill 要求委派。單純寫「快速完成」並不保證觸發多代理。

在 CLI 使用 /agent 檢視與切換代理 thread；App／IDE 的代理活動呈現方式依版本而異。驗收時要看到實際子代理活動及其回傳結果，不能只依主代理說「已分工」。

ENABLE + LIMIT

先確認能力，再限制並行數。

目前版本預設啟用 subagent workflows。CLI／IDE 的設定可在使用者設定檔加入以下區塊；若已有 [agents]，請合併欄位。

版本差異：目前文件也列出 features.multi_agent 功能旗標。舊版教學可能要求開啟實驗功能；現在應先檢查版本、可用工具與組織限制，不必盲目重複加開關。並行數是上限，不是每次一定建立的代理數。
ROLE DESIGN

每個代理都要有邊界與輸出。

角色工作範圍回傳內容
Explorer指定模組，只讀相關檔案、資料流、根因假設
Reviewer指定 diff 與測試，只讀可重現問題、嚴重程度與證據
Worker一個明確變更，限定檔案變更摘要、驗證與待整合事項
主代理協調、比較與整合最終 diff、整合驗證與交付報告

先以自然語言分工即可。若同一種角色反覆出現，再考慮建立自訂 agent。當前官方範例使用 .codex/agents/*.toml 描述 name、description、模型與 developer_instructions，請依版本文件配置。

INTEGRATE

平行完成後，仍需要整體驗證。

  1. 先要求每個代理回報精簡結果與證據，避免大量日誌塞回主對話。
  2. 比較共同假設和互相矛盾的發現，必要時查原始程式。
  3. 修改工作明確分配檔案；跨分支時先合併，再執行相關檢查。
  4. 由主代理確認整合後的行為與完整 diff。
  5. 評估省下的等待時間，是否值得增加的模型與工具用量。

子代理會各自消耗 tokens。Plus 使用者宜從兩個範圍明確的唯讀任務開始，沒有可獨立工作時維持單代理。

TROUBLESHOOT

要求了多代理，卻沒有啟動？

檢查項目下一步
是否明確要求委派指定兩個獨立任務、邊界與輸出
客戶端版本與功能查看 codex --version，對照目前 Subagents 文件
設定與管理限制確認 agents.enabled 與相關 feature 未被停用
工作是否相依先完成共同依賴，再派剩餘的獨立工作
工具與用量是否可用查看實際活動；無法建立時請主代理說明原因並順序完成
判斷：兩個代理都要修改同一個會員元件，應直接同時進行嗎？
