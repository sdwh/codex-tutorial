PLAN ≠ API BILLING

先確認你正在使用哪一種額度。

ChatGPT Plus 包含 Codex 使用權限。以 ChatGPT 帳號登入使用方案額度；API key 的使用走 API 計費，不能把 Plus 當作 API 免費額度。

額度是浮動的。官方說明 ChatGPT Work 與 Codex 共用使用限制，本機與雲端 Codex 工作也共用方案用量，也可能有每週限制。模型、任務大小和執行方式都會影響消耗；請看帳號用量頁的實際剩餘量與重置時間。

CLI 可用 /status 查看目前 session 資訊；帳號可用模型以模型選單為準。下面是本站的工作安排建議，並非額外提高額度的方法。

SPEND ON OUTCOMES

把用量留給需要判斷的地方。

工作情境建議做法原因
格式、短文件、小型修正先選帳號提供的 Luna 等輕量模型範圍清楚，容易驗收
跨模組功能、難以重現的錯誤使用較強模型，補足重現與驗收條件減少錯誤方向造成的返工
架構決策、棘手根因按需提高推理強度在關鍵判斷投入，而非每一步都最高
一般互動先用 Standard 模式Fast 更快但使用方案額度的速率可能更高
獨立的大型查核限定兩個子代理的唯讀範圍平行縮短等待時間，但會增加總用量

比較模型時用同一個小任務：記錄結果是否正確、需要幾輪修正、驗證能否通過。速度與一次回答長度都不能單獨代表效益。

THE HIGH-LEVERAGE LOOP

一次交辦，包含完成與驗證。

  1. 先縮小範圍：提供可重現情境和相關檔案，避免要求掃完整個 repo。
  2. 先釐清不確定處：需求模糊時先分析；確認方向後讓它持續執行到驗收。
  3. 維持相關脈絡：延續同一個任務；改做不相關工作時開新對話。
  4. 保存穩定規則：把常用命令與限制留在 AGENTS.md，不必每輪重貼。
  5. 用證據收尾：驗證失敗要處理，最後回報做了什麼、實際跑了什麼。
WHEN USAGE RUNS LOW

快到限制時，先留下可接續的工作。

下一步很明確

把改動、已完成檢查和下一步存成短交接文件。核對重置時間，恢復後延續同一任務。

仍在探索問題

請 agent 整理已確認證據與排除的假設，避免下次重新搜尋。減少廣泛掃描和無邊界的並行。

官方目前提供 Plus／Pro 額外購買 credits 的選項。是否購買應根據任務急迫性與帳號顯示的費率判斷；切換到 Cloud 或開新對話不會創造獨立的免費額度。

A PRACTICAL SESSION

用一個工作時段練習高效協作。

5 分鐘確認用量、目標與範圍
10 分鐘讀碼與必要規劃
30 分鐘執行與修正
15 分鐘檢查 diff、驗證與交接

這是練習安排，並非模型執行時間保證。完成一個小功能後，檢查哪些回饋可整理成規則；下一次就能少花一輪溝通。
